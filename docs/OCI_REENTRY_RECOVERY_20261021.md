# OCI Grid / DCA 自动重入恢复（2026-10-21）

## 根因及修复边界

- DCA 两腿先后退出，BTC 保留已中止的旧重入批次，而 ETH 没有批次；组合恢复因批次不一致永久等待。
- 只协调两腿均为组合 `REENTRY`、机制相同、没有当前重入意图的情况。旧任务只有在已归档为 `ABORTED`、所有订单均终态、成交数量／成交ID／现金流／手续费与原有入账一致时，才不阻塞新批次。结果不明、未入账、冷却未结束或其他门未放行时不创建订单。
- Grid 完成库存重入后没有安排单对网格刷新，仍等待旧的两小时刷新计时。恢复完成后进入正常的撤单核对／单代重建路径；兼容修复已持久化的旧 `EXPECTED_EMPTY:REENTRY` 状态，不重复买回库存。
- scheduler 的 `ensure_staging()` 会重新发布镜像携带的 Grid 脚本，因此同步更新该镜像中的脚本；只改挂载目录会被覆盖。

不修改模型、风控阈值、历史本金或累计成交。正常恢复的风险周期处理仍使用原有代码，不手工清除风控。Stock 保持原暂停安排。

- DCA Guard 使用原镜像增量封装，只替换 `dca_reentry.py`；scheduler 同样只替换所发布的 Grid 脚本。发布前比较运行环境和挂载，不带入共享环境文件中的无关变更。
- Grid 维护使用正常优雅退出，仅撤销已证明属于 Grid 的普通订单，确认交易所订单为零后加载新代码。保留真实成交、库存及风险状态；两台 DCA、Grid Guard、Report、管理 Bot 不重启。

## 操作与验收入口

`ops/reentry_recovery/` 保存本次受控运维脚本和增量镜像定义。这些脚本绑定本次已核验部署路径，不是通用一键发布命令，重复执行前必须重新核对现网。

`acceptance_oci.py` 只读验证实际交易所挂单、价格方向唯一、SELL 数量不超归属、DCA 控制器实际放行、归属缺口、合同新鲜度、运行代码加载哈希及非目标容器身份。订单数会随成交变化，不作永久运行参数。

本次修复不提交 Git，不修改历史冻结发布包；最终实际验收结果保存在上述 rollout 的 `acceptance.json`。
