# Stock PAPER 存储重设计与暂停规则

本次按用户要求废弃旧模拟账本，保留可恢复备份，暂停 Stock PAPER。Grid、DCA 实盘以及 Hummingbot API 数据库不在清理范围。新版本必须完成隔离验证并获得恢复授权后才运行；删库、构建成功都不代表已恢复模拟交易。

## 数据库重建边界

旧 `hummingbot_stocks` 为 Stock 专用数据库，不能删除共用 PostgreSQL 服务或 `hummingbot_api`。删除前先停止 Stock，验证完整备份，并用最新的经济数据备份在隔离库恢复核对现金、持仓、订单和成交。

新账本不导入旧收益、订单、Executor 或报价水位；旧账只在备份中保留。重新开始时明确模拟本金与新起点，界面不得将旧收益接到新曲线。现有默认模拟本金为 2000 USDC，但本次不创建新 run，也不注入新资金。

## 新存储方案

沿用真实 OrderExecutor 和 PositionExecutor 生命周期，最终撮合仍仅发生在本地 PAPER 账本。现金、库存、成交、费用、订单及恢复检查点继续事务化保存，成交与更新用确定性身份去重；Binance 真实经济请求必须为零，不读取交易 Secret。

行情存储分为三类：最新可信报价和持久化去重水位；实际成交引用的报价证据；用于图表的分钟及小时摘要。不再创建或追加保存所有报价的 `paper_quote_events`，启动时不再扫描或导入旧原始报价。

最近30天保留分钟摘要，第31至370天保留小时摘要；摘要不得参与撮合，也不补造缺失行情。撮合只使用新鲜 Bid、Ask 与实际盘口数量，同一报价不能因重启再次产生流动性。成交及现金变更与报价去重水位在同一事务中提交。

订单、成交、费用、资金、活动 Executor 及恢复证据不因容量或年龄盲删。权益和一般业务历史按370天治理，旧 run 与新 run 隔离。费用按订单累计金额计算，部分成交只收取费用增量；模拟 MTM 使用真实归属现金、库存及可信报价，无法对账时不展示可信盈利。

500 MiB继续作为表和索引容量目标，400／450／500 MiB对应治理、警告及严重告警，不是截断必要经济写入的硬配额。容量须实测，不预先承诺达标。

## 暂停与恢复保护

- `BINANCE_STOCKS_PAPER_PAUSED=true`：在数据库及 Executor 初始化前拒绝启动，直接绕过数据库引导运行应用也不能恢复 PAPER。
- `BINANCE_STOCKS_DATABASE_CREATE_ENABLED=false`：数据库不存在时拒绝自动建库，防止重启后静默重置模拟本金。
- `STOCKS_PAPER_TELEGRAM_TRADING_ENABLED=false`：Telegram 不允许创建、撤销、减仓或关闭模拟 Executor。

Compose 默认保持上述暂停设置。数据库创建需要单独明确授权，PAPER恢复也需显式移除暂停；不能通过打开 LIVE 权限或换模式绕过。保护不改变 Grid/DCA、模型审批或通知 Bot 权限。

旧报价迁移和本次容量维护调度暂停；不继续恢复或转换13 GB旧报价库。旧维护脚本保留审计和隔离测试用途，不能自动承接新 run。

## 验收与恢复步骤

先验证暂停零数据库连接、缺库不自动创建及 Telegram拒绝旧按钮。再在专用隔离库验证新存储没有原始报价表，部分成交、费用、并发、超时、重启、乱序及重复报价不会重复经济成交；回放现金、持仓和净收益核对。

在未创建任何生产模拟订单的情况下构建镜像并保留停止状态。恢复前检查 MARKET_DATA行情新鲜、模式为PAPER、LIVE授权关闭及真实经济请求为零；明确新模拟本金与起点，获得恢复授权后创建新 run。新版本首次启动仍不得自动恢复旧订单，第一笔由用户通过 Telegram 发起。

本轮不恢复交易、不清仓、不兑换资产、不修改 Grid/DCA 库存或模型权限。备份与实际删除结果写入 OCI 私有运维回执，不将生产数据提交到 Git。
