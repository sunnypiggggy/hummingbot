# 强制退出与自动恢复

## 状态机

`ACTIVE → EXITING → COOLDOWN → REENTRY → ACTIVE`。完整性或基础设施故障在清仓后进入 `LATCHED`。

触发顺序：先持久化 `EXITING`，关闭新 BUY/SELL，取消机器人订单，停止创建 Grid 订单或 DCA executor，然后在一个控制周期内提交归属库存的市价退出。

## 双通道执行

1. 风控先持久化`EXITING`并关闭普通BUY/SELL，防止退出期间继续增加风险。
2. 已存在的策略执行器或订单是第一写入者；它们仍活动时，Guard不得并发卖出。
3. 执行器和活动订单终止后，Guard刷新Binance余额与统一归属账本，只对实际残余取得资产租约。
4. Guard使用确定性`clientOrderId`补充退出；请求超时先查询原订单，不能盲目重发。
5. 每个周期按成交、余额、活动订单/executor和归属重新计算剩余数量；持续超时发送严重告警，
   但保持Fail-Closed核对，不得通过第二通道形成重复卖出。

风险退出优先级高于Grid参数刷新、Maker延迟层、DCA普通止盈和无归属库存清理。只有订单、
成交、余额、活动订单/executor四项证据全部核验，且剩余归属低于动态可成交门槛后，才允许
写入`exit_completed_at`。

## 归属边界

- Grid 只出售 `capital_reservations` 中的初始基础币，加该策略审计成交形成的净库存。
- DCA 只出售 `managed_inventory` 加该机器人净成交。
- DCA退出数量使用“启动归属＋已经包含紧急调整的最新净成交－已确认退出量”；紧急成交
  不得再次累加。
- 两策略归属量必须小于等于实际账户余额；没有归属证明不得发送紧急市价单。
- 不使用账户总余额推算退出数量，不出售其他机器人或人工持仓。

交易所 `PRICE_FILTER`、`LOT_SIZE`、`MARKET_LOT_SIZE`、`MIN_NOTIONAL/NOTIONAL` 动态读取；市场单优先使用 `MARKET_LOT_SIZE`。低于步长或最小成交额的残余记录为 dust。

## 冷却时间

| 作用域 | 冷却 |
|---|---:|
| v22 技术 Risk-Off | 0 |
| 单仓止损/持仓保护 | 30分钟 |
| 单策略亏损或回撤 | 6小时 |
| 组合亏损或回撤 | 12小时 |
| 完整性/基础设施 | 不自动恢复，LATCHED |

## 自动重入条件

自动重入使用持久化 `reentry_intents`：提交前先记录风险周期和意图；订单活动中、状态未知或
成交尚未进入 SQLite 时不得补单。部分成交只补已经确认未成交的剩余量，完成回调必须经过
订单、成交、余额和 PairLedger 复核。Pair级和组合级恢复共享同一意图，不能各自重建一份库存。

冷却结束后仍必须同时满足：退出完成、无活动订单或执行器、行情与交易所过滤器新鲜、Guard连续3个周期健康、资金充足、v22/FOMC/其他熔断全部放行、自动重入开关开启。

- Grid 每对按当前价格重建约100 FDUSD基础库存。
- DCA 每机器人重建约95 USDT基础库存。
- 组合恢复要求相关 BTC、ETH 都完成重入；单策略恢复按交易对隔离。
- 实际成交后更新归属清单，建立新风险周期基准和权益峰值；累计实盘盈亏不重置。

## LATCHED

模型缺失、哈希错误、合同过期、周缺失、授权不匹配、监控完整性故障等先取消订单并退出归属库存，完成后锁存。关闭普通机制开关不能解除；必须人工定位原因、恢复健康合同、复核余额和订单并显式 reset。

## 审计字段

每次退出/重入记录机制、作用范围、信号与执行时间、信号价、数量、平均成交价、手续费、滑点、dust、信号后追加亏损、重试次数、剩余风险、冷却截止、健康周期、新风险基准、模型周和相关哈希。
