# 实盘风控韧性策略

## 原则

对能够通过重试、缓存或资金释放自行恢复的故障，系统只缩小交易权限，不执行清仓或人工锁存。只有无法证明数据与授权可信，或故障超过持续时间门槛时，才升级为强制退出。

## 故障分级

| 类型 | 示例 | 临时动作 | 恢复方式 | 是否立即清仓/锁存 |
|---|---|---|---|---|
| 瞬时传输故障 | 超时、连接重置、HTTP 429、Binance 500/502/503/504 | 使用仍在有效期内的已签名合同；关闭不可信的新风险入口并重试 | 数据源恢复后自动清除故障状态 | 否；持续超过宽限期且无有效合同时才升级 |
| DCA 报价资金观察不足 | USDT 被挂单锁定、成交尚未结算、可用余额低于观察预算 | 记录告警与报告状态；不改变普通 BUY/SELL 权限 | 余额恢复后自动清除观察告警 | 否 |
| 自动重入资金不足 | 有资金重建基础币，但重建后无法保留 BUY 侧预算 | 停留在 `REENTRY`，不提交市价重建单 | 资金满足完整双侧预算后自动重试 | 否 |
| 确定性完整性故障 | 模型/特征/策略哈希不匹配、签名或授权错误、交易对不一致 | Fail-Closed，撤单并按归属账本退出 | 修复根因并人工复核 | 是 |
| 持续监控不可用 | Guard 连续失败超过配置阈值 | 从重试状态升级为 Fail-Closed | 修复后按对应恢复流程处理 | 超过阈值后是 |

## DCA 资金观察与重入资金预检

- DCA 运行时资金观察模式固定为 `alert_only`，合同必须同时写明 `enforced=false`。
- 约 `95 USDT` 的单机器人 BUY 侧预算和 `0.2%` 缓冲仅用于告警、报告与容量评估；可用资金低于观察线时，不关闭普通 BUY 或 SELL，也不改变 controller gate。
- 多个 DCA 机器人同时 Risk-On 时，报告仍按机器人数量汇总观察预算，用于发现共享账户资金重复规划，但汇总结果不能单独阻塞交易。
- 自动重入前同时计算基础库存重建预算和重入后的 BUY 侧保留预算；任一不足都不提交市价单。
- 订单实际提交前仍执行交易所余额、最小成交额和策略资金边界硬校验；这些是下单安全条件，不等同于“资金观察门”。
- 资金观察不足不会触发 `EXITING`、`COOLDOWN` 或 `LATCHED`，不会关闭 BUY/SELL，也不会覆盖其他风控门。
- 余额来自统一库存对账周期；30 秒内的最近健康余额可用于抵抗一次瞬时读取失败，避免额外高频调用 Binance 账户接口。

## 传输故障宽限

- Requests 产生的 `500 Server Error` 与 HTTP 429/5xx、连接重置、超时等均归入瞬时传输故障。
- 普通只读 GET 最多执行初始请求加2次退避重试；最后一次可重建连接池。POST/DELETE
  绝不因网络异常自动重放，避免重复下单或重复卖出。
- Grid producer 优先继续发布仍在签名有效期内的最后一份健康合同。
- Grid/DCA Guard 将瞬时故障写入持久化宽限状态；进程重启不会重置首次故障时间。
- 内部GET重试成功只进入四小时统计；持续约6秒才发送一次运行告警，持续60秒才升级
  到现有Fail-Closed。有效合同的`valid_until`不得因宽限而延长。
- 宽限期间不会因单次请求失败出售归属库存或要求 Hermes 解锁。
- 模型哈希、签名、授权和交易对等确定性错误不享受传输宽限。

## 可观测字段

DCA `guard_state.json` 的 `gate_aggregate.capital` 记录：

- `mode=alert_only`
- `enforced=false`
- `buy_ready`
- `free_quote`
- `required_quote`
- `required_with_buffer`
- `reason`
- `observed_at`
- `cached` 与 `cache_age_seconds`

每个机器人同时记录最终 BUY/SELL 权限。`buy_ready` 为观察结果，不参与最终权限 AND；最终权限仍由 v22、FOMC、熔断、完整性、恢复阶段和 controller 落地共同决定。
